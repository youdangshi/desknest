# 桌巢 DeskNest · 后续开发计划（Backlog）

> 2026-10-17 · 记录 v2.0 **砍掉但没删代码**的全部功能，以及补回来的顺序、成本、依赖。
> 原则：**下架 ≠ 删除**。每个被下架的功能，代码文件都还在仓库里，只是从导航/默认构建里摘掉。
> 补回来的标准动作只有三步：① 在 `MainWindow.RegisterPages()` 挂回入口 ② 需要的话加回 csproj 引用 ③ 补冒烟断言。

---

## 0. 为什么要"砍完还得记账"

1. 砍掉的每一样都代表一次**已经写过的功能**，重写成本远高于恢复。
2. 单休 + 晚上 1–2 小时，必须知道"下一件最值钱的事"是什么，而不是凭印象。
3. 将来任何一项补回来，都要先过**这一版的红线**（可关、不弹广告、不上传、不动用户文件）。

## 2. 各项详情

### P1-1 全盘搜索（Alt+Space）

- **砍的原因**：自建 SQLite 索引 328 万条，占空间、首次跑得久；用户已装 Everything。
- **补回来需要**：SearchPanel（在）+ 后端抽象（新）→ 优先接 Everything SDK/IPC；没有 Everything 时退化为"只在盒子里搜"。
- **任务**：① 后端接口 `ISearchBackend` ② Everything 实现 ③ 结果列表复用 `UiKit` ④ 热键 Alt+Space（与 FR-15 的热键机制共用）⑤ 冒烟：结果去重、路径拼接。
- **红线**：不得自建全盘索引（除非用户显式开启），默认只搜盒子。

### P1-2 自定义图标 / 自定义背景

- **砍的原因**：v2.0 先定颜色与材质，图片解码/缓存/内存是另一摊。
- **补回来需要**：图片加载（`BitmapImage` + 缓存上限）、盒子背景层布局、菜单挂到「格子样式 ›」。
- **风险**：大图内存爆；需要限制单图 ≤ 8MB、缓存 ≤ 64MB。

### P1-3 展开方式：向上 / 向下展开

- **现状**：v2.0 只有 始终展开 / 单击展开 / 悬停自动展开。
- **补回来需要**：复用"卷起"的位移逻辑 + 屏幕边缘吸附判断。
- **成本**：小（约 1 个任务）。

### P1-4 胶囊模式

- **是什么**：盒子收成一条细条贴边，鼠标移上去展开。
- **补回来需要**：高度自适应（本版有）+ 贴边磁吸 + 动画。
- **风险**：与"高度自适应"打架，先做自适应再做胶囊。

### P2 桌面组件（7 类）

- **砍的原因**：每类都是一套独立 UI，维护成本比盒子还高。
- **补回来需要**：先恢复**组件宿主**（`DesktopWindows` 的 Widget 部分）+ 一个最简组件（待办）。
- **顺序建议**：待办 → 速记 → 天气 → 性能 → 音乐 → 一览。

### P3 整理与规则（**最危险的一项**）

- **砍的原因**：会真的搬用户文件；历史事故"新建盒子顺手整理，20 个文件消失"。
- **补回来前置条件（缺一不可）**：
  1. 预览（列出每个文件的来源 → 目标）
  2. 执行后**整体回滚**（事务化：要挪的文件清单先落盘）
  3. 默认关闭、每次执行都要确认
  4. 冒烟覆盖"回滚后文件数一致"
- **风险**：即使有回滚，跨盘/占用/权限也会失败；必须有"部分成功"的清楚提示。

### P4 六个模块

- **机制**：`modules\*.dll` 存在才加载；v2.0 已从 csproj 摘除 → 发布包里没有它们。
- **补回来需要**：① csproj 取消注释 ② `CopyModules` 目标恢复 ③ `RegisterPages` 挂回对应页 ④ 冒烟：模块缺失不报错。
- **顺序**：性能 → 统计 → 关机 → API → 桌宠 → AI（越往后依赖越多）。

### P4 盒组 / 抽屉盒 / 待办盒 / 多显示器页

- **多显示器页**：`PagesDisplays.cs` 在；但"移到显示器"菜单项要的是 `Monitors` API，恢复页面即可。
- **盒组**：⚠ 历史上合并后"两盒叠一起谁也点不到"的 bug 出在这；恢复前先写 5 条冒烟。
- **抽屉盒/待办盒**：`BoxKind` 枚举还在，DB 里 kind 字段也还在，恢复要补 UI。
