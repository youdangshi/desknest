## 二、用户与场景

### 2.1 目标用户

1. **主力用户（作者本人）**：单休上班族，桌面常年堆着下载文件、截图、工程目录；要"桌面干净 + 找东西快 + 没有广告"。
2. **同类用户**：用过 360 桌面 / 小智桌面 / DeskBox / DeskTidy，被弹窗、推荐位、右键菜单注入、会员墙劝退的人。
3. **进阶用户**：愿意折腾外观（两套独立令牌、每盒独立样式），也愿意接 AI（本地只读接口）。

### 2.2 三个典型流程

| 场景 | 以前 | 现在（桌巢） |
| --- | --- | --- |
| 桌面堆满 | 手动归类到文件夹，桌面留一堆文件夹 | 拖进桌面上的收纳盒；桌面不留文件夹 |
| 找文件 | 翻资源管理器 / Everything | `Alt+Space` 输入关键字，或直接看盒子里的图标 |
| 想要待办/天气/性能 | 装三四个小组件软件 | 桌面组件模块，可单独开关 |

## 三、功能全景

### 3.1 桌面层（核心）

- **四种收纳盒**：普通盒（文件真的移进数据目录）、映射盒（只存路径）、抽屉盒（可展开面板）、待办盒
- **四种标题栏**：标准 / 紧凑 / 悬浮 / 隐藏（隐藏后 `Alt+拖动` 移动）
- **交互**：拖动、四边+右下角缩放（最小 160×96）、卷起、自动隐藏、双击隐藏（可撤销）、图标/列表视图、滚轮切组、拖文件进出、拖盒子互相合并
- **盒组**：多个盒子叠在一处，标题栏标签或滚轮切换
- **分级右键菜单**：标题样式 / 视图与排序 / 添加格子 / 更多操作（样式作用域、透明度、圆角、双击行为、颜色与材质）

### 3.2 整理

- 文件夹归集 / 桌面分区两种形态；**预览向导**；执行后整体回滚
- 规则整理（扩展名 / 关键词 / 大小 / 时间）+ 定时自动整理（**默认关**）
- 红线：**新建盒子只建空盒子**，整理永远是独立入口（预览 + 可回滚）

### 3.3 搜索

- `Alt+Space` 打开：文件 / 应用 / 命令三类；`↑↓` 选择、`Enter` 打开、`Ctrl+Enter` 所在位置、`Esc` 关闭
- 全盘索引落盘 SQLite，重启不重扫；有"残缺索引不许覆盖完整索引"的保护；数据库可压缩

### 3.4 外观（两套独立令牌）

- `Theme.Shell`（主窗口/设置页）与 `Theme.Desktop`（盒子/组件/桌宠）**互不影响**，可互相复制
- 每套：配色（跟随系统/深色/浅色/纯黑/护眼）、材质（亚克力/云母/纯色）、材质强度、透明度、圆角
- **卡片颜色**（v3.0 新增）：8 个预设 + 跟配色方案；选了浅色卡片，**文字自动转成深色**（对比度 ≥ 4.5:1）

### 3.5 桌面组件（Widget）

文件 / 待办 / 速记 / 天气 / 音乐 / 系统监视 / 一览，共 7 类；可单独关闭。

### 3.6 可选模块（6 个独立 dll，删掉就等于没装）

| 模块 | 内容 |
| --- | --- |
| 桌宠 | 助手型：待办提醒、番茄钟、久坐、CPU 联动；`.petpack` 素材包；打字陪伴默认关 |
| 性能监视 | CPU / 内存 / 网络 / GPU 曲线与条形图，显示项与布局可自选 |
| 使用统计 | 各应用使用时长（**默认只记进程名**） |
| API 面板 | 各模型余额、调用次数、成功率、延迟；密钥 DPAPI 加密 |
| 计划关机 | 定时 / 倒计时 / 空闲，提前提醒可取消 |
| AI 接口 | 只读本地服务（仅 127.0.0.1），给 Codex / dsh / Claude 读盒内清单、待办、统计 |

### 3.7 外壳与维护

托盘、开机自启、单实例、备份与回滚、诊断包、检查更新、多显示器页（一键搬运/防跑丢）。

## 五、核心机制（大白话）

**盒子为什么"贴在桌面上"？** Windows 的桌面本身是一个特殊窗口。我们让盒子窗口**沉到图标列表的下方**、并且不抢焦点：任何窗口都能盖住它，点它才临时置顶。
（历史：曾试过把盒子挂成桌面的子窗口，结果"看不见也点不到"，已回退。改进方向见 `docs/11` P0-1。）

**拖动为什么不糊？** 系统自带的"拖动窗口"对这类窗口会静默失效却返回成功，所以拖动一律自己算（`WindowDrag` 手动增量 + DPI 换算），`PointToScreen` 是物理像素、`Left/Top` 是 DIP。

**整理会不会弄丢文件？** 整理前一定预览；执行后可**整体回滚**；删盒子会把盒内文件**逐个还原**到原位置，原位置不存在就回退到桌面。

**模块化怎么做到"删掉就没"？** 模块编译成独立 dll 放在 `modules\\`，宿主扫描不到就等于没装：不加载、不占内存、导航里也不出现。

**外观改动怎么保证"看得见"？** 所有外观参数最终收敛到**一个纯函数** `ThemeTokens.ResolveCardPaint()`（颜色 + 材质 + 材质强度 + 透明度 → 一个像素），盒子与组件都走它，冒烟验证器直接对像素断言。

## 六、数据与隐私

| 项 | 说明 |
| --- | --- |
| 数据目录 | `%LOCALAPPDATA%\DeskNest`（可用 `DESKNEST_DATA_DIR` 改；测试时用它做隔离很安全） |
| 存什么 | 设置 JSON + 一个 SQLite（盒子/条目/待办/统计/索引）；盒内文件真的移动到 `用户目录\DeskNest\<盒子名>` |
| 联网 | 只有两件事：**查天气（默认关）**、**检查更新（点按钮或开开关才查）**；都不上传本机信息 |
| AI 接口 | 只监听 `127.0.0.1`、只读、有授权开关 |
| 不做 | 不注册系统右键菜单、不弹广告/推荐、不上传数据、无付费墙、不做壁纸库 |

## 七、技术架构

```
界面层 DeskNest.App (WPF)      窗口、15 个页面、控件、外观令牌
业务层 DeskNest.Core           数据(SQLite)、整理逻辑、搜索、备份、模块宿主
原生层 DeskNest.Native         Win32：桌面层、拖动、显示器、热键、电源、DPAPI
模块 DeskNest.Module.*         6 个可选 dll（不含在默认构建里的 ComfyUI 已移除）
工具 tools/DeskNest.Smoke      冒烟验证器（唯一自动化验收手段）
```

- UI 库：WPF-UI 4.3（MIT）；数据库：Microsoft.Data.Sqlite
- 版本号只有一处：`src\DeskNest.App\DeskNest.App.csproj` 的 `<Version>`
- **发布体积**（同一份代码实测）：依赖框架 **9.4 MB**（zip 4.0 MB，需 .NET 10 桌面运行时）／ 自包含单文件+压缩 **70.5 MB**／ 自包含普通 **164.6 MB**（zip 71.2 MB）。WPF 不支持裁剪与 NativeAOT，详见 `docs/11` P2-3。

## 九、发布与更新

1. 改版本号（一处）→ 2. 编译 + 冒烟 + 截图 → 3. `publish` → 4. 提交推送 → 5. GitHub 打 tag / 发 Release（写更新说明）
2. 「关于」页的检查更新读 `repos/youdangshi/desknest/releases/latest`，认 `v1.2.3` / `1.2.3-beta` 这类写法；网络不通只给一句中文说明，不弹错误框。
3. 发版建议：同时提供**轻量版**（4.0 MB，需 .NET 运行时）与**免安装版**（70.5 MB 单文件），关于页标出"你装的是哪个版本"。

## 十二、已知限制

1. 盒子是普通可激活窗口：会被别的程序盖住、Win+D 会一起收走（P0-1 解决）。
2. 调试版模块页只出现 2 个（桌宠/性能），其余模块页在 Release/发布版才齐。
3. `dotnet test` 在本机跑不起来（testhost Access Denied），自动化验收走冒烟验证器。
4. 未签名 exe 会触发 Windows「无法验证发布者」提示，正式发版建议加代码签名。
