## 1. 最关键的发现：我们的组导航方案要改

我们 `docs/23` 写的是 **「标题栏下加一条标签条，最多 4 个标签 + ▾ 其他 N 个」**（抄 Fences 的思路）。
DeskBox 的做法完全不同，而且在它的规范里**明确否掉了"外置标签条"**：

> 格子组只在现有标题栏内提供一个常驻成员选择器，**不增加第二行导航、内容区选择按钮、外置标签条、嵌套胶囊或视觉卡片堆**。

它的标题栏长这样（原规范 R2）：

```text
┌ [成员图标] 当前成员  2/4  ▾      可拖动区域      ⋯  ︿ ┐
│                         当前成员内容                  │
└──────────────────────────────────────────────────────┘
```

**为什么它的方案更好（对我们尤其如此）**：

| 维度 | 标签条（Fences 式，我们原方案） | 单选择器 + Flyout（DeskBox） |
| --- | --- | --- |
| 垂直空间 | 多占 28–32px，盒子本来就小 | **零额外高度**，复用标题栏 |
| 成员多了怎么办 | 要溢出菜单，还得排序、滚动 | 列表能装任意多个，天然可滚动 |
| 切换时布局 | 标签宽度变化 → 标题被挤压跳动 | 图标/名称/箭头**固定槽位**，不跳位 |
| 拖动 vs 点击冲突 | 标签条要挖一块拖动热区 | 选择器区排除拖动区，其余整条都能拖 |
| 实现量 | 标签容器 + 溢出 + 拖出移出 + 排序 | 一个按钮 + 一个 Flyout |

**结论：采纳 DeskBox 方案，废弃标签条。** 我们 2026-10-17 写的「最多 4 个标签 + 更多」整套规则作废。

### 采纳的组导航规则（从它的规范里逐条搬，值直接可用）

1. **一个选择器**：显示「成员图标 + 当前成员名 + `2/4` + ▾」，点击打开锚定 Flyout；
2. **切换不改窗口**：`SurfaceId`/HWND/位置/尺寸/层级/锁定/展开状态**都不变**（我们对应的是盒子窗口的 hwnd 与 rect 不动，只换内容 —— 与用户 10-17 拍板的"组统一尺寸"一致）；
3. **列表内容**：每项显示图标 + 完整名称，当前项用选中背景 + 勾；
4. **管理分区单独放**：排序、移出、解散**不要混在选择列表里**，单独一个分区（这条救了我们的「右键菜单一长串」问题）；
5. **失败要能回滚**：目标成员准备超过 150ms 才显示进度；失败保留当前项并给非阻塞提示，不静默换成员；
6. **键盘等价路径**：`Alt+↓`/`Enter`/`Space` 打开列表，`Ctrl+Tab` 下一个、`Ctrl+Shift+Tab` 上一个（**这是纯键盘用户唯一能用组的方式，我们的 WPF 版必须做**）；
7. **滚轮是可选增强**：只在选择器热区、指针进入 150ms 后才启用，提交后冷却 180–220ms，首尾不循环，可在设置里关掉；
8. **组标题显示三档**：`IconAndText`（默认）/ `IconOnly` / `TextOnly`，图标槽固定，缺图标用占位、不许文字跳位；
9. **`2/4` 是辅助信息**：可在窄宽度断点隐藏，但切换过程中不许变布局；
10. **不是所有盒子都能合并**：只有「标准/紧凑」两种标题栏模式允许；覆盖层/隐藏/系统模式禁止，并且要**显示禁用原因**，不许从候选里静默移除。

### 我们暂不采纳的两条

| 它做的 | 我们不照搬的理由 |
| --- | --- |
| 标题栏内**局部滚轮**切换 | 桌面盒窗口在桌面层，滚轮事件容易和"滚动盒子内容"打架；先做点击+键盘，滚轮放 P2 且默认关 |
| 组级标题的 `Auto` 图文策略（明确不做） | 我们的标题栏窄，直接给三档固定值，用户选一次即可 |

## 2. 胶囊收起（我们的"卷起"）

它把「收起」做成**四档行为 + 展开方向**，比我们现在的「卷起/展开」二元要细：

```text
收起行为：System（跟随全局） / Expanded（保持展开） / Click（点击才收） / Smart（智能）
展开方向：跟随全局 / 自动 / 向上 / 向下
另有：恢复自动宽度（CompactWidth 被手动拉过之后才可用）
```

关键设计点（值得抄）：

- **每一档都带"跟随全局"选项**：单盒覆盖不等于要你重设一遍，默认值来自全局设置，菜单里显示成「跟随全局（当前：点击才收）」；
- **覆盖值单独存**（`WidgetCollapseBehaviorNames.GetOverride`），没设置就是 null，不是把全局值复制一份；
- **恢复自动宽度**是独立菜单项，且当宽度没被手动改过时**禁用而不是隐藏**（用户能看到"为什么现在不能点"）。

对应到我们：

| 我们现在的字段 | 改成 |
| --- | --- |
| `BoxRecord.RolledUp`（布尔） | 拆成 `CollapseBehavior`（4 值）+ `ExpandedDirection`（4 值）+ `CompactWidth`（可空） |
| 标题栏「︿/﹀」按钮只做一次开合 | 按钮行为由 `CollapseBehavior` 决定；`Smart` = 展开状态下鼠标离开 2s 自动收、有内容滚动条时不收 |
| 收起后显示「N 项」 | 保留，但加宽度上限（`HorizontalMinimumWidth=96` 这类下限在它算法里，我们收起态最窄也要 ≥ 96×36） |

## 3. 组合排列（胶囊排队算法）

`WidgetCapsuleArrangementCalculator` 是纯函数，逻辑干净，**可以直接翻译成 C# 用在我们的桌面层**（同一个语言，几乎逐行搬）：

- 输入：成员列表（Id/宽/高）、工作区矩形、锚点、锚点位置（四角）、方向（横/纵）、间距；
- **横向 = 单行、纵向 = 单列**（不做多行网格，避免"到底排到哪"）；
- 统一高度 = 成员最大高度，**卡在工作区高度内**；
- 宽度有下限 `96`（横向）/ 高度下限 `36`（纵向），总宽超了先**压缩间距**再压缩成员宽度（`FitPrimarySizes`）；
- 锚点在右/下时反向排布；
- 最后整体 `ClampGroupIntoWorkArea`，保证整组不越界。

我们现在的 `WindowDrag`/盒子组用的是"统一尺寸 + 逐个摆放"，没有"整组不越界"和"间距自适应压缩"。**这两条要补**：
盒子组拖到屏幕边缘时整组收进来，而不是让最右那个盒子出去一半。

## 4. 不适用 / 要改造的部分

| DeskBox | 我们的情况 | 处理 |
| --- | --- | --- |
| WinUI 3 控件（`MenuFlyoutSubItem`、`NavigationView`） | 我们是 WPF + WPF-UI | 换成 `ContextMenu`/`MenuItem`/自定义 Flyout，交互规则照搬，实现重写 |
| `*.resw` 本地化键（`Widget.CollapseBehavior.Title`） | 我们是硬编码中文 + 未来做多语言 | 先照抄文案结构，键名保留以便将来抽资源 |
| `SurfaceId`/重宿主体系统 | 我们每个盒子一个 HWND，没有"组宿主"概念 | **这一层不抄**：我们组的做法是"同组盒子共用一套 rect/尺寸，只有活动成员可见"，比它轻 |
| Rust 原生 ABI（`native/`） | 我们没这块 | 跳过 |
| 自动整理事务（`DesktopOrganizationTransaction`） | 我们有 `OrganizeEngine` + 回滚 | 只在"冲突检测"上参考，不搬实现 |
