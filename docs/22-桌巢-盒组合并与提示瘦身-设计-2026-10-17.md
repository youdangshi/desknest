## 一、为什么合并不了（根因确定）

合并入口只有两个：盒子右键菜单「添加格子 › 并入本组」、把盒子拖到另一个盒子上。

`src/DeskNest.App/Windows/BoxWindow.Menu.cs:181`：

```csharp
.Where(b => b.Id != _box.Id && !string.Equals(b.GroupId, _box.GroupId, StringComparison.OrdinalIgnoreCase))
```

两个**普通盒子**的 `GroupId` 都是 `null`，而 `string.Equals(null, null)` 返回 **true** → 被判定成"已经在同一个组里"→ 过滤掉。结果是右键菜单永远显示

> 「没有其他盒子可并入」

**修法**：把 `!string.Equals(a,b)` 换成 `b.GroupId != _box.GroupId`（`null != null` 为 false… 即两个都没组时视为不同组，可以合并）。一行改动，不影响已在组内的盒子。

补充事实：设置页「组件组 → 合并」这条路本身是通的（日志里 14:46 / 14:50 / 15:29 三次合并都是它），所以「合并不了」指的是桌面右键菜单这条路。

## 二、合并后的标题切换

现成件：`RefreshGroupTabsPublic()` 把成员名画成标签（文字 + 2px 强调色下划线），点击 → `SwitchToMember` → `Desktop.SwitchGroupTo`（显示选中、隐藏其余、`ReloadItems`）。

要补四件事：

1. **合并后两个窗口都刷新标签**。现在只刷新当前显示的那个，另一个要等切过去才画出来，看起来像"没合并"。
2. **标签条限宽 + 省略号**。盒子窄的时候标签会把右侧 4 个按钮挤出去：标签条设 `MaxWidth = 标题栏宽 − 按钮区 − 关闭`，单个标签超长截断，多于 3 个用滚轮横向切换（`group.wheelSwitch` 默认开）。
3. **合并基准 = 你右键的那个盒**：位置、尺寸、圆角都保留当前盒，被并进来的盒对齐过来（现在就是这个语义，补测试锁死）。
4. 成员 ≤1 时不画标签条（解散后自动复原）。

## 三、提示弹窗瘦身：128 → 约 25

现状统计（`Notifications.Toast(` 调用点，全项目 **128 处**）：

| 类别 | 数量 | 处理 |
| --- | --- | --- |
| 「已…」成功确认（已锁定、已套用、已切换、已合并、已添加…） | **42** | **全删**，改成界面自身反馈（勾选态、标签高亮、列表刷新） |
| 失败 / 错误 | 34 | 保留，统一走 `Warn`（黄），可关闭 |
| 引导 / 一次性说明 | 6 | 保留 |
| 其他（后台完成、版本提示、热键提示…） | 46 | 逐条判断 |

判断标准一句话：**只有"你没看见就会出事"的才弹**——失败、可撤销的破坏操作（收纳 / 解散 / 删除）、后台任务完成、首次引导。其余靠界面自己说话。

具体删的第一批（举例）：
`已锁定位置/大小`、`标题样式：…`、`已把当前盒的外观应用到所有盒`、`已把当前盒的显示样式套用到所有盒`、`已新建文件夹：…`、`已合并：A + B`、`已把「B」并进「A」`（合并本身在界面看得见）、`已切换素材包`、`已定位到 …`、`已保存/已添加待办/已删除`（列表已经变了）。

保留的：`解散/删除/移除 → 还原 N 项 + 撤销`、`收纳完成 N 个 + 撤销`、`「xxx」不是文件，收不进盒子…`、`尺寸已锁定：…取消勾选即可拉伸`、`检测到 N 个窗口跑到屏幕外`、`有新版本`、`桌巢已在后台运行`。

### 3.1 你已拍板：**更狠版**（2026-10-17）

成功类**全部不弹**，包括「已解散」「已删除」「已收纳」。判定表改成：

| 类别 | 数量 | 处理 |
| --- | --- | --- |
| 「已…」/「成功」 | 42+ | **全删**，含解散 / 删除 / 收纳 |
| 失败 / 错误 | 34 | 保留（黄色、可关闭） |
| 后台完成（自动整理、升级、跑出屏幕救援） | ~8 | 保留 |
| 首次引导（首次启动、热键说明） | ~4 | 保留 |
| 其余说明类 | ~40 | 删，改为界面自身反馈 |

**撤销不能跟着弹窗一起消失**，改两个常驻入口（不弹窗）：
1. 主窗口「概览」页顶部一条「最近一次操作：解散「工作」还原 12 项 · 撤销」，存在 10 分钟；
2. 托盘右键菜单加「撤销上一次收纳 / 解散」。

预计 toast 调用点 **128 → 12 左右**。

## 四、验收标准（我改完自己先过一遍再交你）

1. 右键 A → 添加格子 → 出现「＋ B」→ 点它：A 顶部出现 B 标签，两盒位置尺寸一致，文件仍在各自目录。
2. 点标签 B：显示 B 的内容、A 隐藏；点回 A 恢复；来回切换 3 次不错位。
3. 盒子拉到很窄：右侧 4 个按钮仍在最右，标签变省略号。
4. 解散组：两个盒子恢复独立，位置错开 24px 不重叠。
5. 合并 / 切换 / 锁定 / 套用样式：**不弹窗**。
6. 真失败（锁定大小后拖边）：仍弹，黄色，可关闭。
7. 冒烟从 56 项扩到 ≥59 项全过（新增：合并过滤、标签切换、解散错位）。

## 五、范围与风险

- 不做（进 Backlog）：虚拟盒、组改名、跨屏组、标签拖拽排序。
- 风险：`SwitchGroupTo` 每次都 `ReloadItems`，大盒子切换可能 100–300ms 卡顿；先量，超过 500ms 再加缓存。
- 提交粒化：合并修复 1 条、标签 1 条、弹窗瘦身 1 条，各自可回滚。
