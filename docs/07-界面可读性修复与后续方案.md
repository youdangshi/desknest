## 一、你截图里那个"看不清"到底是什么问题

### 1.1 现象

外观与主题页：下拉框、滑杆、按钮都能看见，但**每一行的标题和说明几乎消失**；左侧导航也一样，只剩图标。

### 1.2 三个根因（已定位到代码）

| # | 根因 | 具体表现 |
| --- | --- | --- |
| **1** | `IsDark`（明暗判定）**靠时间猜**，而不是由配色方案决定 | 你选的是"护眼"（浅奶油底 + 深棕字）。夜里 19:00 之后 `IsDark` 返回 `true` → 卡片取深色 `#28282E`，文字却是为浅底准备的深棕 `#2B2418` → **深底深字** |
| **2** | 运行时换主题**只重画页面内容，没重画窗口外壳** | 主窗口背景/前景只在启动构造时设定一次；切换配色后外壳仍是旧的深色，而页面里的文字已经换成新配色的颜色 → 两者错配 |
| **3** | 次要文字用"前景色 + 透明度"而不是实色 | 透明度会与身后不同表面（背景 / 卡片 / 悬停淡底）混出不同结果，容易糊成一片 |

### 1.3 已经修好的部分（本轮，已提交）

1. **明暗判定改为由配色决定**：深色/纯黑＝深色族；浅色/护眼＝浅色族；只有"跟随系统"才按时间近似。
2. **主窗口订阅主题变更**：换配色时同时重画外壳（背景/前景）+ 导航 + 当前页；桌面盒与组件窗口也一起刷新。
3. **次要/辅助文字改实色**（与背景混合后的固定色），不再用透明度叠加。
4. **新增 9 项对比度回归测试**（`ThemeContrastTests`）：四套配色下，正文对背景、正文对卡片都要求 ≥ 4.5:1，次要文字 ≥ 3:1，辅助文字 ≥ 2:1；并断言"护眼/浅色永不被判成深色"。**当前 52 项测试全绿。**

> 也就是说：现在这版**已经把"看不清"这个 bug 修掉了**。你可以直接跑 `dist\DeskNest-1.0.0\DeskNest.exe` 验证（跑之前我会重新发布一次）。

## 二、界面方案（请你选一个，再往下我都按这个做）

### 方案 A：保守修复（在现有基础上继续打磨）

- 内容：四套配色逐项实测对比度、自绘细滚动条、修掉剩余 P2（底部标题裁切、长说明换行时图标居中）、设置页加"下钻 + 面包屑"
- 观感：就是现在这种"左栏图标导航 + 白/深卡片 + 行式设置"，只是更干净
- 工作量：约 0.5 天；风险：低（不引入新依赖）

### 方案 B：引入成熟 Fluent 控件库（lepoco/wpfui，MIT）

- 内容：直接用它的 `NavigationView`、`SettingsCard`、`SettingsExpander`、`FluentWindow`（Mica 标题栏）重写外壳与设置页
- 观感：**最接近 DeskBox 的 WinUI 3 质感**（因为它就是把 Fluent 控件搬到 WPF）
- 工作量：约 2–3 天（要重写外壳 + 全部设置页，并适配其主题资源）；风险：中（多一个第三方依赖，版本升级要跟）

### 方案 C：自绘 Fluent 外壳（介于 A 与 B 之间）

- 内容：保留现有组件库，但自己实现：整窗 Mica、自绘标题栏（含窗口按钮）、细滚动条、下钻页面包屑、设置卡片悬停态；配色仍由我们控制
- 观感：接近 B（不引入依赖），细节打磨靠自己
- 工作量：约 1–1.5 天；风险：低到中（自绘标题栏要处理最大化/贴边/多显示器）

### 我的看法（既然你让我说）

**先 A 后 C**：A 让现在的版本立刻干净可用，C 把"质感"这件事补齐；只有在你想"完全对齐 WinUI3 观感、并且不介意多一个依赖"时才走 B。

三个方案都会包含同一套底线：所有文字按 WCAG AA 校验、四套配色实测、设置页统一"图标 + 标题 + 说明 + 右侧控件"、交互三态（悬停/按下/禁用）齐备。
