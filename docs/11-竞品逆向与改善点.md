## 一、一页结论

| 结论 | 一句话 |
| --- | --- |
| 最值得学的一家 | **DeskBox**：同样是"叠在桌面上的盒子"，它用 **owner 窗口**而不是 `SetParent`——既贴壁纸，又能点能拖，还**不进 Alt+Tab** |

## 二、DeskBox 1.5.7（你最想学的那个）

### 2.1 它是什么做的（大白话）

- **【事实】** 安装包是 **Inno Setup 6.7.3**（`_re\deskbox_install\install.log`：`Setup version: Inno Setup version 6.7.3`），PE32，33 MB（E1/E2）。
- **【事实】** 主程序 `DeskBox.exe` 51 MB，**不是 .NET 托管程序**：REA 原话 `"The PE has no CLI data directory; managed metadata and CIL are unavailable."`（E3）。
- **【推断】** 所以它是 **.NET + NativeAOT 编成原生 exe**（与源码 `<PublishAot>true</PublishAot>` 对得上）→ 不用装运行时、启动快、安装包小。
- **【事实】** 源码 `Tianyu199509/DeskBox`：`net10.0-windows10.0.22621.0`、`UseWinUI=true`、`WindowsAppSDK 2.5.1`、`WinUIEx`、`H.NotifyIcon.WinUI`、`CommunityToolkit.Mvvm`、`Markdig`；界面 **WinUI 3**（不是 WPF）；`native/` 是 **Rust**；`installer/` 是 Inno Setup。
- **【事实】** 安装目录里有 `EverythingSdk.dll`、`Microsoft.Windows.Widgets.dll`、`WebView2Loader.dll`、`NPUDetect.dll`。

### 2.2 它是怎么"贴"在桌面上的（本条最关键）

**【事实】源码 `src/DeskBox/Services/WidgetLayerService.cs`：** 用 `FindWindowEx(HWnd, IntPtr.Zero, "SHELLDLL_DefView", null)` 找到桌面图标层窗口，
`SetWindowLongPtr(hwnd, GWLP_HWNDPARENT, desktopIconView)` 把它设成**自己窗口的 owner**（注释写着 `Never force WorkerW creation here`），再用 `SetWindowPos(..., HWND_BOTTOM, ...)` 贴到底。
窗口样式：`WS_EX_TOOLWINDOW` + `appWindow.IsShownInSwitchers = false`（不进 Alt+Tab）；防抢焦点：`WM_MOUSEACTIVATE → MA_NOACTIVATE`。

**【事实】另两家独立实现走的是同一条路**（读源码得到，见第五节）：
- **WitchDrawer**（同为 C#/WPF）：`src/WitchDrawer.Native/Windows/DesktopToolWindow.cs` 注释 `"Makes the Shell desktop the owner of this top-level WPF window"`，
  Win11 用 Progman、**Win10 取 WorkerW** 当 owner，配 `WS_EX_TOOLWINDOW|WS_EX_NOACTIVATE` + `SWP_NOOWNERZORDER`；
  还**修正 Progman 的 last-active-popup**，否则按 Win+D 会把盒子一起激活。
- **ZenDesktop** 的图标模组：走 `SHELLDLL_DefView → SysListView32` 的 ShowWindow。
- 三家都**不用 `SetParent`**。

**【推断】** 为什么 owner 比 SetParent 好：`SetParent` 会真的改变父子关系（渲染/输入/DPI 全跟着变），而 owner 只影响 Z 序与"跟着最小化"，
所以窗口仍然是正常顶层窗口——**能点能拖**，同时沉在图标下方。

**【对照我们】** 我们在 `DesktopLayer.Attach` 试过 `SetParent` 到 WorkerW，结果是"看不见也点不到"（`docs/10` 13.1），于是退成普通可激活窗口，
代价是**被别的程序盖住、Win+D 一起收走**（13.2 第 1 条）。**现在三家样本摆在面前，这条路值得重试。**

**【未知】** DeskBox 只承诺 Win11，本机是 **Win10 22H2**；WitchDrawer 明确给了 Win10 分支（取 WorkerW + 压 Z 序兜底），正好可参考。

### 2.3 外观 / 主题系统

- **【事实】** 材质 **5 种**：`Acrylic / AcrylicBase / Mica / MicaAlt / Solid`；圆角 3 档；边框颜色×粗细各 3 档；背景可"材质/统一图片/全景"；遮罩默认 35%。
- **【事实】** 落地用 `MicaController` / `DesktopAcrylicController` + `DWMWA_SYSTEMBACKDROP_TYPE`，失败按 [80, 240, 580] ms 重试。
- **【事实】** 设置页度量（`Styles/SettingsOverviewResources.xaml`）：行高 **64**、内边距 **16,10**、图标文字间距 **20**、卡片圆角 **6**、按钮高 **34**/最小宽 **104**、页标题 **28**/小节 15/正文 14/说明 12、设置项 = **卡片（标题+一句说明+右侧控件）**、有**设置内搜索**。
  → 这些数值我们 `docs/10` 第七节**已经对齐**，说明上一轮逆向没白做。

### 2.4 UI 怎么搭的 + 美术资源（重点）

- **【事实】** UI 是 **XAML（WinUI 3）**：`Views/`、`Controls/`、`ViewModels/`（CommunityToolkit.Mvvm）；设置页有专属资源字典 `Styles/SettingsOverviewResources.xaml`。图标**两套混用**：`<FontIcon Glyph="&#xE790;">`（系统 Segoe Fluent 字形）+ 自带 SVG。
- **【事实】** `Assets\` 共 **91 个文件**（来自 `E:\RJ\DeskBox\DeskBox.InstallManifest.txt`，386 行）：

| 目录/文件 | 内容 | 数量 |
| --- | --- | --- |
| `SettingsNavIcons\` | 设置页导航 SVG（general/appearance/interaction/file-widget/feature-widgets/capsule-mode/maintenance/about） | 8 |
| `WeatherIcons\` | 天气图标 **4 种风格**（默认 / `flat\` / `fluent\` / `line\`，每套 ~13 SVG） | ~56 |
| `WeatherIcons\LICENSE-fluent-emoji.txt`、`LICENSE-meteocons.txt` | **第三方素材许可原文随包分发** | 2 |

  **差距不在"有没有图标"，在"有没有成体系、带许可说明的素材目录"。**

### 2.5 功能清单（源码+安装目录）

**【事实】** 文件格子（托管/映射、图标与列表）、文件堆栈（3×3/5×5）、完整 Shell 拖放、复制/剪切/重命名/删除/在资源管理器显示、空格快速预览、
格子分组（标题/滚轮/Ctrl+Tab）、桌面整理（分类预览→建文件夹或复用格子、下载目录按"停留时间"自动整理）、待办（截止/提醒/重复/附件/Markdown）、
快速记录、**桌面搜索（复用 Everything IPC，不自建索引）**、Glance/天气/音乐组件、**胶囊模式**、托盘+全局热键、备份/云同步/更新/诊断、**12 种语言**。

### 2.6 ⚠️ 法律边界

- **【事实】** 仓库 `LICENSE` = **GPL-3.0**；README：`"Earlier DeskBox versions already published under the MIT License remain available under that license. The change is not retroactive."`
  逐标签核对：`v1.0.0` = MIT；`v1.3.7`/`v1.4.0`/`v1.5.8` = **GPL-3.0**；源文件头写 `// Copyright (c) DeskBox. All rights reserved.`
- ✅ **可以学**：界面数值、材质枚举思路、**owner 贴桌面这个 Win32 公开手法**、打包发布方式。
- ❌ **不能抄**：v1.3.7 之后任何 `.cs`/`.xaml`（GPL 传染会逼我们转协议）、`Strings/*.json` 文案、`Assets/` 图片、以及 "DeskBox" 名号。
- ⚠️ 唯一能合法复用代码的是 **v1.0.0 的 MIT 快照**，但它没有 1.1 之后的任何改进，**建议不用**。

## 七、改善点清单（P0/P1/P2）——**都还没动手**

### P0-1 盒子被别的程序盖住、Win+D 一起收走

- **现象**：`docs/10` 13.2 第 1 条。
- **对方怎么做**：**三家**都用 owner 而不是 `SetParent`（DeskBox：`GWLP_HWNDPARENT=SHELLDLL_DefView` + `HWND_BOTTOM`；WitchDrawer：Progman/Win10 WorkerW + **修 last-active-popup** + `WS_EX_TOOLWINDOW|WS_EX_NOACTIVATE`；ZenDesktop 图标模组同理）。
- **我们建议**：开**实验分支**把 `DesktopLayer.Attach` 改成 owner 路线，**先探测 SHELLDLL_DefView，取不到就回退**（Wallpaper Engine 会重构层级），保留"挂不上=普通窗口"兜底和设置开关。
  成功标准：贴在壁纸之上图标之下、能被别的窗口盖住，但 **Win+D 不收走、点得到、不抢焦点**。
- **改哪里**：`src\DeskNest.Native\Win32\DesktopLayer.cs`、`WindowStyles.cs`、`src\DeskNest.App\Windows\DesktopWindows.cs`、`BoxWindow.cs`（`WM_MOUSEACTIVATE`）。
- **需要你**：**必须你亲手试**（本机鼠标注入无效）。风险：Win10 需调；**失败就回退，不影响现版本**。

### P0-2 改外观参数盒子颜色不变（本轮已修，剩一处待拍板）

- **现象**：你原话"改窗口的外观参数盒子的颜色根本不变"。
- **根因**：盒底绘制只读 `Background`/`Opacity`，`Material`/`MaterialIntensity` 从没参与绘制；产品里也没有"卡片颜色"入口。
- **已做**：`ThemeTokens` 加"卡片颜色"覆盖项；把"颜色+材质+材质强度+透明度"合成纯函数 `ResolveCardPaint()`，盒子与组件都走它；外观页加**「卡片颜色」色板（8 预设 + 跟配色方案）**；**选浅色卡片时文字自动变深**；冒烟加 **13 项**断言。详见 `docs/10` 13.1 与第十节。
- **待拍板**：**"全局一个色 + 每盒可覆盖" 还是 "只做每盒"**。目前只做了**全局**（改动最小、不碰数据库）；"每盒覆盖"要给 `boxes`/`widgets` 加 `card_color` 列 + 盒子菜单「更多操作」加一项。

### P0-3 外观页"改了看不见"，缺即时预览

- **现象**：拖完滑块只能靠记忆比较。
- **对方怎么做**：DeskBox 设置项 = 卡片（标题+说明+控件），材质/圆角**当场反映在真实格子上**。
- **我们建议**：外观页顶部加一块**"预览卡片"**（真实底色/材质/圆角），改参数立刻重画。
- **改哪里**：`src\DeskNest.App\Pages\PagesSettings.cs`（复用 `Theme.ResolveCardPaint()`）。

### P1-1 美术资源体系几乎是空的

- **现象**：`Assets\` 只有 2 个文件，没有"能换风格"的图形资产。

- **改哪里**：`src\DeskNest.App\Assets\`、`DeskNest.App.csproj`（显式 Content）、`THIRD-PARTY-NOTICES.md`。

### P1-2 15 个设置页平铺（缺分组与设置内搜索）
