# 桌面收纳盒交互调研（2026-10-17）

> 目的：收纳盒的交互（合并成标签、点标签切换、卷起、拉大小、提示）不靠拍脑袋，先看成熟产品怎么做，再定我们的规则。
> 来源：Stardock Fences 6（商业，桌面栅栏 + 原生标签）、DeskBox（开源，桌面格子 + 胶囊）、Microsoft 通知与触控目标指南。

## 一、四家怎么做的

### 1. Fences 6：把两个栅栏拖到一起就变成标签

- 拖一个栅栏到另一个上，松手提示 **「Drop to add tab」**，松手后变成带标签的栅栏组。
- 组内**只有一套尺寸**：标签切换不改变栅栏的大小，位置与大小属于"组"。
- 调整顺序：按住 **Shift 拖标签**；或右键标签选「左移/右移」。
- 退出组：**Shift 拖出栅栏范围**，松手放回桌面（该栅栏恢复独立）。
- 标签样式四选一：**Menu only（标签隐藏，只能从右键菜单切）**、Flat、Segmented、Rounded。
- 依据：<https://www.stardock.com/blog/535507/getting-started-with-tabs-in-fences-6>、<https://support.stardock.com/space/SHC/2814444096/Fences+6++UI:+Tabs>

### 2. DeskBox：标题栏分成三段，各有各的职责

- 标题栏左中右三段：**左侧图标区 = 只负责拖动（不触发自动展开）**、**中间标题区 = 悬停/点击展开**、**右侧操作区 = 按钮 + 六点拖动手柄**。
- 「收起」入口**固定在标题栏最右**，不受"悬停按钮"开关影响。
- 收起态（胶囊）与展开态的宽度关系有两种：**保持同宽（默认）**、**独立调整**；独立模式下"改右边框时左边不动"。
- 展开/收起有**锚点**：靠近屏幕左侧就向右展开，靠近底部就向上展开，**锚点不漂移**。
- 拖文件靠近胶囊时**临时展开**，让你确认落点，松手后回到收起态。
- 双击标题 = 重命名；交互期间（拖放、菜单、调尺寸）**临时提升窗口层级**，结束恢复。
- 依据：<https://github.com/Tianyu199509/DeskBox/blob/b264d640ee5353f46aff25bfc06649dc6ef439cb/docs/user-guide/05-capsule-mode.md>、<https://github.com/Tianyu199509/DeskBox/blob/b264d640ee5353f46aff25bfc06649dc6ef439cb/docs/user-guide/07-appearance-and-interaction.md>

### 3. Microsoft：提示别吵，目标别小

- 通知设计原则：**"Notifications should not be noisy"**——过多打断会让人关掉整个通知渠道；能静默投递的就别弹。
- 触控目标：**7.5mm 见方（135PPI、1.0 缩放下约 40×40px）**；高频操作的目标还可以更大。
- 依据：<https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/app-notifications-ux-guidance>、<https://learn.microsoft.com/en-us/windows/apps/develop/input/guidelines-for-targeting>

## 二、对照我们的设计，谁对谁错

| 议题 | 业界做法 | 我们原来的 | 结论 |
| --- | --- | --- | --- |
| 合并手势 | 拖 A 到 B 上，松手前提示「Drop to add tab」 | 拖拽 + 菜单「添加格子 › 并入本组」 | **保留两条**，但拖拽必须给"松开即合并到「X」"的实时提示（已有） |
| 切换是否改尺寸 | **组一套尺寸**，切换只换内容（Fences 6） | 先写"跟着成员变"，你已纠正 | **组统一尺寸**，与业界一致 ✅ |
| 标签溢出 | Fences 提供「Menu only」把标签收进右键菜单 | 无处理 | 标签超过 4 个 → 折叠成「▾ 其他 N 个」下拉，不再横向滚动 |
| 退出组 | Shift 把标签拖出栅栏 | 只有「解散组」 | 加一个轻手势：**把标签拖出盒子范围** = 移出该标签所在盒（保留菜单项） |
| 标题栏分区 | 左图标=拖动、中间=标题/展开、右=操作 | 整条标题栏都可拖，按钮贴右 | 保留整条可拖（桌面盒不需要"展开"语义），但**图标区不响应双击**，避免误触重命名 |
| 拉大小 | 触控目标 ≥40px；Win32 原生边框 4–8px | 边 10px、右下角 20px，且只有右下角命中 | 边 **12px**、四角 **40px**（触控标准的一半以上）、角上画可见抓手 |
| 卷起 | DeskBox 的胶囊：收起只剩标题 + 数量 | 收到标题栏高 | 保留；**收起时标题栏右侧显示「N 项」**，空盒显示「空」 |
| 提示 | 少弹、可静默 | 128 处 | 12 处左右（见 docs/22 §3.1） |

## 三、因此要改的三处

1. **抓手**：四边 12px、四角 40px（对齐 7.5mm 触控目标），抓手 `ZIndex` 置顶，进入边缘换光标；右下角保留三点提示。
2. **标签条**：最多显示 4 个标签，其余收进「▾ N」下拉；标签过长省略号；右键标签有「左移 / 右移 / 移出」。
3. **卷起**：收到标题栏高，标题右侧显示项数（DeskBox 的胶囊信息密度做法）。

## 四、不学的地方

- Fences 的四种标签样式（Menu only / Flat / Segmented / Rounded）：我们只做一种（文字 + 下划线），样式多了反而增加设置负担。
- DeskBox 的「悬停展开」：桌面盒是常驻的，不需要。
- 组内标签拖拽排序：进 Backlog，v2.1 再说。
