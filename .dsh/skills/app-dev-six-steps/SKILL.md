# 六步法：把一句需求做成能用的软件

> 来源：用户提供的「零基础用 AI 打造专属 APP」流程图（六步）。
> 本机已在 DeskNest（C#/WPF/.NET 10）项目上跑通整套流程，下面的坑都是踩过的。

## 铁律（比步骤更重要）

1. **每步先出设计，用户点头才动代码。** 设计 = 改哪几个文件 + 交互怎么变 + 验收标准。
2. **一步一验收，不要攒到最后。** 每步结束交「可点的东西 + 怎么判过」。
3. **一条一提交**，提交信息写「改了什么 + 为什么」，能单独回滚。
4. **产品决策一次只问一个问题**；技术诊断可以连着问，但别把选择题塞给用户。
5. **自己先验，再交用户。** 交出去的每一条，都要有"我怎么知道的"证据（截图/日志/测试）。

## 第 1 步：对话澄清需求

**目标**：把"我想要个桌面整理工具"变成可验收的一句话。

做法：
- 先问「最痛的是哪一件事」，不要一次问十项；
- 用「谁、什么时候、点哪里、期望看到什么」四要素改写需求；
- 拿不准的**写成两种可选方案**（甲/乙）让用户挑，不要自己替他定；
- 明确红线：哪些动作绝对不能做（例：绝不自动移动用户桌面文件）。

产出：`docs/<项目>-需求与红线.md`，一页以内。
判过：用户能复述，且能指出哪句写得不对。

## 第 2 步：生成页面结构（页面树 + 区块）

**目标**：先定"有哪些页、每页有什么块"，再谈像素。

做法：
- 画页面树（一级导航 ≤ 6 项，二级页面用「列表 → 点进去 → 分组折叠」，**不许平铺**）；
- 每页标三件事：这块显示什么数据、有哪些操作、空态长什么样；
- 桌面类软件额外定：窗口层级、是否贴桌面层、DPI 缩放、多屏行为。

产出：`docs/<项目>-页面结构.md`（含文字版线框）。
判过：用户能指着某一页说"这块我要放 X"。

## 第 3 步：输出 PRD

**目标**：一份人和 AI 都能照着做的产品文档。

必须包含：
- 背景与目标（一句话）；
- 功能清单（每条带验收标准，写成"做了什么 → 看到什么"）；
- 明确不做的（进 Backlog，附理由）；
- 数据与隐私边界（存哪、传不传、怎么删）；
- 术语表（同一个东西在全项目只有一个叫法）。

判过：随便挑一条功能，用户和 AI 的理解一致。

## 第 4 步：制定开发计划（切片 + 依赖）

**目标**：把 PRD 切成能独立验收的小片。

做法：
- 每片 ≤ 半天工作量，带"完成判据"；
- 标依赖（谁必须在谁之前）；
- 先做「能站在用户面前被点」的那片（垂直切片），不要先铺基础设施；
- 每片写清「验收方式：自动 / 人工 / 截图」。

产出：`docs/<项目>-开发计划.md`（T1…Tn）。
判过：用户认可顺序，且知道第一批能看到什么。

## 第 5 步：验收测试与 Bug 记录

**目标**：把"我觉得能用"变成"有证据能用"。

三件套：
1. **自动门禁**：冒烟测试（本机惯例：`tools/<项目>.Smoke`，一条断言一个 Check，跑完打印 `通过 N 项，失败 0 项`）；
2. **人工清单**：8～15 条，每条写"动作 → 期望 → 现象"，用户逐条回「过 / 不过 + 现象」；
3. **Bug 表**：ID / 现象 / 根因（读到代码哪一行）/ 设计要点 / 验收标准 / 优先级。

关键纪律：
- 「文字看不清」这类主观问题**必须量化**：截图 → 逐像素量对比度（见下文工具）；
- 用户说"不行"时，先问「是颜色丑、布局坏、文字看不清、还是一操作就闪」，四类修法完全不同；
- 每条 Bug 都要能落回一行代码或一条设计规则，否则继续查。

产出：`docs/<项目>-验收记录与二次开发清单.md`。

## 第 6 步：Git 存证与二次开发

- 每个可验收的切片一次提交；发版打 tag；
- 提交前必须：编译 0 错误 + 冒烟全过 + 至少一张关键截图；
- 二次开发（Backlog）单独一份文档，别混进当前计划；
- 交接给别的 agent 时写 `HANDOFF-<日期>.md`：现状一句话、怎么跑、已拍板决策、已知坑、下一步。

## 自验证工具箱（这套是本机最有用的部分）

### 1) 自己出图，不等用户截图

凡是能给 App 加"截图模式"，就加：把每个页面按固定尺寸摆好、逐页 `PrintWindow` 存 PNG。
DeskNest 的用法：

```powershell
# 隔离数据目录，绝不碰用户真实数据
$env:DESKNEST_DATA_DIR = "<项目>\_data\light"
dotnet exec "<项目>\src\App\bin\Debug\net10.0-windows\App.dll" --shot-pages "<项目>\_shots\light"
```

深色/浅色各跑一次（预写 settings.json 里的配色键），就有两套对照图。

### 2) 逐像素量对比度，别靠肉眼

```powershell
Add-Type -AssemblyName System.Drawing
$bmp=[System.Drawing.Bitmap]::FromFile($png)
# 取一块区域的最暗/最亮像素，套 WCAG 公式：(L1+5)/(L2+5)
```

判据：正文 ≥ 7:1，次要文字 ≥ 3.5:1（11–12px 小字至少 4.5:1 更稳）。
DeskNest 实测过一次 1.06:1 —— 白底白字，肉眼第一眼还真不一定说得清。

### 3) 把"契约"写进冒烟

"深色主题必须白字"这种承诺，要写成测试：五套配色逐套断言对比度，CI 一跑就知道有没有回退。

### 4) 日志当证据

关键路径都写日志（主题应用、窗口背景、页面切换、合并/解散）。用户报"闪/变色"时，先看日志时间线：
DeskNest 就是这样发现"不透明/跟随材质"每秒翻转 5 次的循环。

## 本机坑清单（Windows + WPF + DSH 沙箱）

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| 沙箱编译 | `生成失败，0 个错误` | `dotnet build <csproj> -c Debug --no-restore -m:1 -nr:false`（MSBuild 多进程节点用命名管道，沙箱禁） |
| 不能走 .slnx | restore 目标要写沙箱外目录，直接失败 | 单项目 + `--no-restore`（obj/ 里已有 assets 即可） |
| 应用跑不起来 | `SQLite Error 8: readonly database` | 应用要写 `%LOCALAPPDATA%`，沙箱只读 → 必须让用户启动，或用 unsandboxed 启动器 |
| UIA 点击 WPF 导航 | 进程直接消失 | 别用 `invoke` 点 NavigationViewItem；优先用"截图模式"验证，其次才是坐标点击 |
| `app_launch` | 反复调用会 45s 超时 | 当作一次性工具用，别当循环里的启动器 |
| `.cmd` 换行 | `'桌巢：run.cmd' 不是内部或外部命令` | 批处理必须 CRLF + ASCII（含中文注释也不行） |
| `.ps1` 编码 | 中文变乱码 | 存 UTF-8 **带 BOM** |
| 中文路径 | 各种"找不到" | 命令里少写中文；必须写时确认编码链路 |
| 运行中的 app 占 DLL | 编译报文件被占用 | 让用户托盘退出；或 `-p:OutDir=` 编到另一个目录 |


## 一句话总结

**六步法的价值不在步骤本身，而在于每步都有"能被别人验证的产出"**：
设计能被点头、计划能被排序、验收能被量出来、提交能被回滚。
